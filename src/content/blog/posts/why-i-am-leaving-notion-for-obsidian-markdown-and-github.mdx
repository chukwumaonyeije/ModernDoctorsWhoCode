Most of my personal knowledge management already lives in Obsidian and GitHub. I still have Notion after many years of using it. Increasingly, I cannot justify keeping another system around the work I am already doing elsewhere.

That is why I am leaving.

The replacement sounds more complicated when I say it aloud: Obsidian, Markdown files, Git, and GitHub repositories. There are more names to explain. There are more mechanics to understand. But the number of products in a sentence does not tell me how much friction a system creates in practice.

I want my notes close to the work they support. I want to open them without reconstructing the application that originally held them. And I want a clear reason for every recurring expense.

## The cost of keeping another place current

Years of using a tool give it a place in your habits. They do not automatically give it a place in your future workflow.

The question I keep returning to is simple: what work still needs to happen in Notion?

When most of my knowledge already lives in Obsidian and GitHub, maintaining another destination introduces decisions. Where should this note go? Which copy should I update? Where will I look for it six months from now?

I think of this as the maintenance cost of a second home. Even an attractive second home needs attention.

A subscription is only part of that cost. The larger expense is maintaining an organizational system that no longer matches where I write, build, and retrieve information.

## Markdown gives the writing a durable form

Markdown is plain text with a small amount of formatting. A heading starts with a hash mark. A link includes a label and a destination. The file remains readable before an application renders it.

That simplicity matters to me. A note can be useful in a writing application, a code editor, or a repository. I can search its text and revise it with ordinary tools.

Obsidian stores notes as local Markdown files inside a folder called a vault. Other text editors can read and change those files too. That is a practical property of the storage model, not a promise about a future export. [Obsidian documents that model here](https://help.obsidian.md/Files+and+folders/How+Obsidian+stores+data).

I still need to be deliberate about portability. Plugin behavior and application-specific formatting do not necessarily travel with the text. The more I rely on ordinary headings, links, and paragraphs, the less reconstruction another editor will require.

The writing deserves a longer life than my preference for any particular application.

## Obsidian and GitHub have different jobs

The system I am moving toward has a straightforward division of responsibility:

| Part | Job |
| --- | --- |
| Markdown | Holds the written content in readable files |
| Obsidian | Provides a workspace for reading, writing, and connecting notes |
| Git | Records changes I explicitly commit |
| GitHub | Hosts repositories so the committed work is available remotely |

A repository is a collection of files with a recorded history. That makes it useful for more than application code. Documentation, project decisions, and written explanations can live alongside the work they describe.

This blog is a concrete example. Its articles live in the repository as Markdown or MDX source files. The site turns those files into published pages. Writing and implementation already share a working environment here.

That relationship is what makes the repository system useful to me. A project explanation can stay near the project. Changes can be reviewed. Earlier committed versions can be recovered.

Git and GitHub are separate pieces. Saving a note does not automatically commit it, and committing it does not automatically push it to GitHub. That distinction introduces responsibility, but it also makes the mechanics explicit.

## Free matters when the work is already there

I am willing to pay for software that earns its place. I have less reason to pay for an additional workspace when the essential work already happens elsewhere.

Obsidian is free to use, including for work. Its Sync and Publish services are optional paid additions. That distinction matters: using the application for free does not mean every service around it is free. [Obsidian pricing](https://obsidian.md/pricing).

GitHub Free includes unlimited public and private repositories, with feature and usage limits. It provides a free starting point for storing text-based knowledge without making every GitHub capability free or unlimited. [GitHub plan documentation](https://docs.github.com/en/get-started/learning-about-github/githubs-plans).

For my personal knowledge management, that changes the calculation. The tools already holding most of my material can support the core workflow without another required subscription.

There is still a cost in time. Organizing files, managing changes, and resolving conflicts are work. I accept that tradeoff because these are skills and habits that also serve my development projects.

## The complexity is real

I would not describe Git as effortless note synchronization. Editing the same file in two places can create a conflict. A remote repository only contains what has reached it. Version history also does not replace an independent backup plan.

Those limitations belong in the decision.

For someone who does not already work with files and repositories, this arrangement can add substantial overhead. For me, GitHub is already part of the environment. Moving more of my knowledge into that environment reduces the number of separate systems I need to sustain.

The useful measure is the effort required to keep the whole workflow coherent.

## A better home still requires better habits

In [The Physician's Second Brain series](/blog/the-physicians-second-brain-series-overview), I wrote about knowledge systems that become collections we stop using. Moving to Obsidian does not exempt me from that problem.

A folder can become a graveyard as easily as a workspace. A graph of connected notes does not prove that I can find the right idea when I need it.

My standard is practical: can I retrieve the material, understand why I kept it, and use it in current work? The file format helps preserve access. The repository helps preserve committed changes. I still have to make the material worth returning to.

After many years with Notion, I am choosing the tools that fit where my work now lives. Markdown holds the writing. Obsidian gives me a place to think with it. GitHub gives the repository-based work a remote home.

I want to spend my time developing the knowledge, with fewer places to keep it current.
